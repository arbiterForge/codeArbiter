## Problem

The release lane's backlog (issues #570, #623, #626, #627) mixes: a genuinely dangerous gap (an ancestry-blind baseline selection that can silently reuse or retarget a version), two narrow reliability defects (an untimed internal Git probe; an overloaded confirmation exit code), a CI-tooling honesty gap (a shim documenting an API that doesn't exist, a silent basename collision, an uncaught exception on a malformed declaration), and a readability defect (one 1,700-word unbroken Phase-2 procedure paragraph with no per-obligation test mapping). Left alone, each increases the chance an operator or an automated caller trusts a check that doesn't actually protect them.

**Caller.** An agent (Claude Code, Codex, or Pi) or a maintainer running the installed `/release` skill in a consuming project; the shared `_releaselib`/`releasehash` helpers those hosts vendor byte-identically; this repository's own CI version gate (`payload_version_gate.py`); and the maintainer reviewing this sprint's PR.

**Done** looks like: every distinct finding across the four issues has an explicit, evidence-backed current disposition (fixed-here / already-fixed-elsewhere / explicitly deferred as out of bounded scope); the in-scope behavioral gaps are closed with regression tests that fail before the fix and pass after; the Phase-2 procedure is traversable without reorganizing its already-correct policy; and the sprint lands as an open PR with fresh proof against the exact candidate, not a claim of shipped release.

**Out of scope (explicit, not merely deprioritized):** any automatic-publisher redesign, a new provider/publisher backend, an offline publication mode, unattended first-time target authorization, an alternate commit-gate, a universal manifest writer, a release-rule DSL, public command/skill expansion, a governance-mode change, `--farm`, a broad onboarding refactor, moving the tag-provenance manifest, rewriting old tags/history, or changing host authority adapters. Two `#570` sub-findings are explicit residuals, not implemented here (see AC-01): the two states the release lane cannot resolve without a configured remote (`gh release view`/`gh release list` unreachable), and back-fill's hardcoded `app` display name / `prefix: v` (a module constant never derived from the consumer's own tags or manifest). Neither is covered by any acceptance criterion below; both get an explicit "acknowledged, deferred — out of this sprint's bounded scope" line in the closing triage report so they are not silently dropped.

F1's most recent comment (2026-09-17, from the repository owner) already contains a complete, verified fix and regression-test idiom, deliberately withheld pending this sprint's version-advance and CHANGELOG-placement decisions — this sprint reuses that design rather than re-deriving it.
- #626's CI-shim doc gap, basename-collision, and uncaught-`ReleaseTargetsError` findings all still reproduce line-for-line against current `.github/scripts/_releaselib.py` and `payload_version_gate.py`.

- #570's ancestry-blind `last_tag_select()` (pure numeric-max scan, no reachability check against HEAD) and the most recent clean blind-exercise run's finding that breaking commits (`feat!`, `BREAKING CHANGE:` footer) are invisible in the composed changelog/tag/notes both still reproduce against current source. The latter is the single most-validated item in this scope: it is what the last blind-exercise run (of thirteen) found on a clean pass.

No material drift invalidates any proposed acceptance criterion. Two Phase-1 findings materially changed the plan from the handoff's draft, both resolved before this spec was written (details in the accompanying decision record, not restated here): the typed-HTML artifact engine the handoff assumed available is not installed in this environment (confirmed via a live call to the actual `_artifactlib.py` bridge, which raised `CAPABILITY_MISSING`) — resolved as a user-approved scoped exception to author this spec/plan pair in legacy Markdown; and a `brainstorming`/`SPRINT.md` approval-gate conflict (auto-approval vs. mandatory explicit STOP) — resolved in favor of `SPRINT.md`'s stricter, more specific rule.

## Approach

Make small, deterministic corrections at each defect's owning source (the shared helper, the CI-only shim, or the skill's own prose), each backed by a regression that fails before and passes after. Reorganize the already-correct Phase-2 procedure into named, ordered substeps without changing its policy — a pure readability restructure, proven behavior-preserving by mapping every existing literal assertion to its new location before any text moves. Close with one bounded independent blind exercise of the exact rendered candidate. This is the only sane approach for a closure sprint: the alternative (rewriting the release lane's policy, or deferring the ancestry gap to a future "bigger" release-hardening effort) either exceeds this sprint's explicit boundary or leaves a known version-corruption vector live. Nothing here contradicts an accepted ADR — ADR-0031 (canonical shared sources) is honored by touching `core/pysrc/`/`core/surface/` first and regenerating host copies mechanically; DECISION-0034 (pre-tag commands are check-only, never mutate) is preserved as-is by the timeout fix, which changes probe *timing* behavior, never turns the probe into a fixer.

## Scope

**In scope**, each traced to its owning issue:
- #627 — bound the internal `release_tree_status()` Git-status probe with a timeout; disambiguate `releasehash.py`'s overloaded exit code 2 into distinct usage/unknown-target/valid-check outcomes; preserve runner semantics, confirmation authority, and digest/marker behavior exactly.
- #626 — correct the CI shim's false importable-wrapper documentation; reject duplicate payload-basename declarations; catch and cleanly report declaration-file errors at the CI version-gate boundary.
- #570 (bounded) — refuse a release baseline that is not a verified ancestor of the candidate history before any release edit; fail before tracked-file writes when commit-gate or branch prerequisites are missing; correct back-fill's "never again" claim to be checkout/file-scoped, not project-global, and move its branch refusal before its declaration write; make breaking-change commits visible in composed release notes and prefer the first breaking entry for a major-bump headline.
- #623 — split the monolithic Phase-2 procedure into named, ordered, behavior-preserving substeps with an explicit invariant-to-test traceability map.
- Necessary generated host-copy regeneration, focused regression tests, version/changelog metadata reconciliation for the affected targets, and an honest final disposition record for all four issues.

**Explicitly not in scope**, beyond the Problem section's boundary: a fully onboarding-free release path for a zero-state consumer (prerequisite refusal is a safety mitigation, not that capability); maintenance-branch version-allocation policy (ancestry refusal detects unsafe ambiguity, it does not implement branch-aware allocation); the two remote-dependent #570 states and back-fill's hardcoded target-name defect (explicit residuals, see Problem section); repairing the `brainstorming`/`SPRINT.md` approval inconsistency as a side task (resolved for this sprint only, not fixed at the source); the typed-HTML artifact-engine payload publication (tracked separately, outside this sprint).

## Decided parameters

- **P1 — Sprint size.** Bounded to AC-01–AC-19 below. The rest of `#570` (the two remote-dependent states, back-fill's hardcoded name) is explicitly dispositioned as deferred, never silently dropped. AC-19 is the user-authorized post-review repair of HIGH-T23R2-1 only; it does not reopen the other deferred findings.
- **P2 — Internal probe timeout.** 30 seconds, matching every one of the module's other 12 internal Git-probe call sites; named and documented; does not apply to operator-declared `pre-tag` commands.
- **P3 — Error-code migration.** Existing valid-check outcomes 0 (confirmed/no-commands), 1 (changed), 2 (never-confirmed, current overload target), 3/4 (declaration-file outcomes) keep their meaning for the confirmed/no-commands/changed/declaration-file cases; malformed usage returns 64, an unknown target returns 65, and "never-confirmed" keeps 2 as its sole remaining meaning. Actual current callers of the code-2 overload are inventoried as part of implementing this (not before), since the caller set can only be verified by reading the code that dispatches on it; if that inventory surfaces an external, unmigratable caller, implementation stops and this becomes a hard-gate escalation rather than a silent workaround.
- **P4 — CI-shim surface.** Correct the documentation only; do not add the absent `select_release_target_by_name` importable wrapper. A future discovered caller that genuinely needs importable access is a plan amendment, not something this sprint adds speculatively.
- **P5 — Ancestry.** Refuse a selected baseline that is not a verified ancestor of (or is unresolvable against) the candidate's history, before any release edit. Zero-tag first-release handling and existing version-policy selection are unaffected. This does not choose a lower version or implement maintenance-branch policy.
- **P6 — Missing prerequisites.** Fail before any tracked-file write when the actual routed commit-gate's prerequisites or branch restrictions are unmet; explain the missing setup. This is a mitigation against a misleading adoption promise, not a new onboarding-free mode — kept as an explicit open item, never described as solving onboarding. (Checked and unrelated: `#829`, merged to `origin/main`, added a "host-owned prerequisite authority adapter" — that is a structured-artifact *plan-task* confirmation mechanism for the HTML engine's own rollout, a coincidental name collision with this AC's release-lane commit-gate prerequisites. Do not attempt to reuse it here.)
- **P7 — Breaking-change visibility.** Reuse the existing `classify_commit`/`classify_window` breaking field (already computed, never surfaced) to add an explicit "Breaking" grouping in composed release notes, and prefer the first breaking entry for a major-bump title. Authored note text and version arithmetic are unchanged; ordinary nonbreaking changes are never mislabeled.
- **P8 — Final review budget.** The original final-candidate exercise budget remains exactly two rounds, both historically spent by T-23; neither result may be rewritten, downgraded, or hand-cleared. On 2026-09-22, after T-24 closed that attempt with HIGH-T23R2-1 unresolved, the user explicitly rejected accepting or overriding the finding and reopened implementation for a concrete repair. That instruction authorizes one bounded verification of the materially changed R-06 candidate under T-25. It is a new, user-directed remediation cycle, not a third attempt to force the prior candidate to pass, and it ends after that verification whether clean or blocked.
- **P9 — Spec/plan artifact format.** Legacy Markdown (this file and its paired plan), per your explicit resolution of the Phase-1 capability gap: the typed-HTML engine this sprint would otherwise default to is not installed in any cached plugin version (confirmed via a live `_artifactlib.py` `CAPABILITY_MISSING` response), and the upstream rollout that will eventually ship it (merged to `origin/main`, not yet in a published release) explicitly lists "publish the real release cohort" as still outstanding. Reconverting this pair to HTML once that payload publishes is a residual, not this sprint's work.

No new dependencies, no change to operator-command time limits, no automatic marker renewal, and no repository-setting change, per the handoff's stated defaults — none of the acceptance criteria below require any of these.

## Acceptance criteria

**AC-01 — Bounded issue reconciliation.** Every distinct finding in #570 (including all thirteen blind-exercise-campaign comment rounds), #623, #626, and #627 receives an explicit current disposition — fixed-here, already-fixed-elsewhere (cite the commit), or explicitly deferred as out of bounded scope — with original provenance preserved and fixed-commit separated from fixed-release. The two #570 remote-dependent states and back-fill's hardcoded target-name defect each get their own "acknowledged, deferred" line; neither is silently absent from the record.

**AC-02 — Bound the internal status probe.** When `release_tree_status()`'s Git subprocess exceeds 30 seconds, it returns a failed probe with an actionable timeout diagnostic — never an uncaught `TimeoutExpired`, never a false "mutation detected," never success. Git selection, environment sanitization, repository root, and target-aware pathspecs are unchanged.

**AC-03 — Preserve runner semantics.** A clean successful probe and a dirty successful probe both return code zero; only porcelain output distinguishes them. A probe failure reaches `clean-tree-status` as a failure and `run-pre-tag` through its existing probe-failure path (never its mutation-detected path). Operator-declared `pre-tag` commands never inherit the internal probe's timeout.

**AC-04 — Disambiguate `releasehash` errors.** Malformed usage returns 64; an unknown target returns 65; each documented and tested. Existing callers stop cleanly on a usage/configuration error rather than being routed to the record-confirmation path.

**AC-05 — Confirmation authority is unchanged.** Digest construction, existing confirmation markers, target separation, and the read-before-record requirement are byte-identical to today. A malformed or unknown-target invocation creates no marker. Every currently valid confirmation remains valid.

**AC-06 — Truthful CI-shim API.** The shim no longer documents an importable `select_release_target_by_name` wrapper that does not exist; it documents the real `select-target-named` CLI route instead. Existing exports and named-selection behavior are unchanged.

**AC-07 — Reject basename collisions.** Two declared payload directories sharing a basename (with equal or different prefixes) are rejected with a diagnostic naming both conflicting declarations, before any map entry is overwritten. A non-colliding declaration's mapping is unaffected.

**AC-08 — Clean declaration-error reporting.** A missing, malformed, or unreadable target declaration on the version-gate's lookup path returns the gate's normal failure status with an actionable, path-identifying diagnostic — never an uncaught traceback, never a silently substituted default map. Existing passing and early-return cases are unaffected; `ca-pi`'s separate gate ownership is preserved.

**AC-09 — Reject an ambiguous ancestry baseline.** Before any release edit, a selected series baseline that does not resolve to a commit reachable from the candidate's history stops with the tag and the cause — never a silent fallback to an older tag, never namespace reuse, never a tag move or delete. A genuine ancestor and a genuine zero-tag first release retain today's behavior exactly.

**AC-10 — Fail before an unavailable commit path.** Before any back-fill or release tracked-file write, the actual routed commit-gate's prerequisites and branch restrictions are checked; a missing prerequisite stops with an accurate next action before any mutation. No invented verification command, no silent onboarding, no commit-gate bypass — and this is never described as delivering a fully onboarding-free release.

**AC-11 — Correct branch-scoped back-fill claims.** Back-fill's behavior is described (and now ordered) in terms of file existence in the current checkout/branch, never as an irreversible project-wide fact. Default/protected-branch refusal happens before the declaration write. Existing-file and malformed-file refusal are unchanged.

**AC-12 — Keep breaking changes visible.** `feat!:`, `feat(scope)!:`, and a `BREAKING CHANGE:` footer are surfaced with an explicit Breaking marker in composed release notes, reusing the existing classification (never a second parser). A major-bump title prefers the first breaking entry over the existing minor/patch fallback. Authored note text and version arithmetic are unchanged; nonbreaking changes are never labeled breaking.

**AC-13 — Traversable Phase 2.** The monolithic step becomes named, ordered substeps covering inputs, committed-section reconstruction, ref snapshot/peeling, publication-state lookup, classification, permitted tag creation, stored-message verification, and report/authorization handoff. The hosted-only boundary and every existing STOP/BLOCK point are preserved; no competing executable correction paragraph exists afterward.

**AC-14 — Invariant-to-evidence traceability.** Every retained normative obligation and affected literal assertion maps to its new instruction location and a proving test. Historical rationale may move to a packaged reference; every decision-point guard stays in the procedure. No assertion is deleted or weakened to make the restructure pass.

**AC-15 — Preserve portable generated delivery.** Shared mechanisms and templates change only at their canonical owner (`core/pysrc/`, `core/surface/`) and regenerate every affected host projection mechanically. CI-only fixes (the shim, the version gate) stay CI-only and are never projected into the portable release lane. No new public skill, command, rule DSL, or second release implementation is introduced.

**AC-16 — Prove the candidate that actually changed.** Fresh named-test outcomes are recorded against identified candidate bytes, with zero-test and skipped results distinguished from passes. Any test that archives HEAD runs against the intended committed candidate or a documented exact-byte scratch fixture — never silently against stale HEAD. Generated-consistency and affected packaged-consumer checks pass before readiness is claimed.

**AC-17 — Preserve the publisher and version boundaries.** No change to automatic-release triggers, publish permissions, cohort continuation, immutable-tag rules, npm publishing, or provenance semantics. Required target versions and synchronized metadata are derived from the live declared release process for only the targets this sprint actually touches — never preassigned, never bumping a target (e.g. `ca-sandbox`) whose payload didn't change.

**AC-18 — Refresh proof and close honestly.** After final generation and tests, a real bounded blind exercise (per P8) runs against the exact rendered release skill, recording helper identities and limitations as evidence; the freshness check passes for those exact bytes. Every issue's disposition (AC-01) is current in the closing report; `#570`'s residual items are never described as fixed, and an open PR is never described as a shipped release.

**AC-19 — Close HIGH-T23R2-1 without an override.** `backfill-detect` declares the existing strict changelog-reconciliation ledger; Back-fill classifies the exact published default-branch history before writing, requires operator-authored `changelog`/`reason`/`authorization` entries bound to full published SHAs, validates the ledger, commits the declaration and ledger together, and stops until both are published on the default branch. A fresh non-default release branch can then widen the first-release window and clear historical missing-footer findings only through exact published reconciliations. Missing, malformed, invented, unpublished, non-ancestor, or incomplete evidence remains fail-closed. A real disposable Git fixture proves the complete pre-footer-history route.
