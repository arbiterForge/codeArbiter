Ship-set evidence inputs

Bind structured-artifact evidence to what would actually be pushed, exempt hook telemetry, cut snapshot handle opens, and give reply capture enough hook time.

Intent

INTENT-01

Intent

CallerUsers and agents running structured-artifact builds (/ca:feature, /ca:sprint) whose verification and review receipts bind to the snapshot input identity.
OutcomeEvidence covers exactly what would be committed and pushed, hook audit appends never stale it, snapshots are fast enough for reply capture, and typed replies are not killed by the host hook timeout.
ProblemThe input identity hashes every file on disk, so a write that will never be pushed (a hook appending to gate-events.log, local scratch) stales every receipt and stalls the build; and a snapshot takes 15-30s on Windows, which also makes reply capture exceed the 30s UserPromptSubmit limit.

Approach

APPROACH-01

Approach

Binding decision refs
  • DEC-01
  • DEC-02
  • DEC-04
ChoiceCompute the input identity from git's ship set (tracked plus untracked non-ignored files) with `.codearbiter/gate-events.log` as the single fixed runtime exemption, keep the existing walk for non-git roots, and reduce portable-store handle opens to one per directory and file. Ship the #931 hook timeout alongside.
TradeoffHonoring git's ignore rules removes noise and hand-kept excludes but means ignored local state that influences tests no longer stales evidence; exact-head hosted CI covers that gap. Commit binding was declined because it needs per-task commits and still requires a clean-tree check.

Decisions

DEC-01

Membership rule

Authorityproposed
ChoiceShip set = `git ls-files --stage` entries present on disk plus `git ls-files --others --exclude-standard`, honoring repository .gitignore, .git/info/exclude and core.excludesFile, then narrowed by plan roots and exclude_directories.
RationaleMatches the ruling that only what would be pushed counts (SRC-05); reuses existing probes (SRC-07).
DEC-02

Fixed exemption

Authorityproposed
ChoiceExactly `.codearbiter/gate-events.log` is exempt, as an engine constant.
RationaleHook-written telemetry, appended on nearly every command; keeping it tracked preserves the audit trail (SRC-08).
DEC-03

Non-git roots

Authorityproposed
ChoiceFall back to the existing filesystem walk; manifest records `membership: filesystem` vs `git_ship_set`. A git root whose probe fails is an error, never a fallback.
RationaleMost Go and Python artifact fixtures snapshot non-git temp directories; failing closed would churn them without benefit.
DEC-04

Speed method

Authorityproposed
ChoiceWalk-relative access: one directory handle per visited directory and one open per input file per scan; file metadata from that handle; no per-file ancestor re-check.
RationaleProfile shows handle opens dominate (SRC-04); ancestors are already validated by the walk.
DEC-05

Manifest version

Authorityproposed
Choicecodearbiter.verification-inputs/0.2.0.
RationaleMembership semantics change; old identities must not compare equal.
DEC-06

Hook timeout

Authorityproposed
Choice600 seconds on Claude and Codex prompt-submit.py UserPromptSubmit entries.
RationaleAbove the 120s engine client timeout with headroom for multiple engine calls; matches the locally verified patch.
DEC-07

Evidence reuse

Authorityproposed
ChoiceReuse validated evidence objects within one engine operation, keyed by content hash and held no longer than that operation's store handle. The snapshot validates receipt chains in a second phase, from the bytes its scan already read.
RationaleThe CP-02 quality review found receipt validation re-reading each chain from the root. authority.Vector, Load and LatestTaskCompletion repeat the same reads, and Vector runs on every read operation. Content addressing makes reuse safe: the hash is checked before an object is kept, and nothing outlives the operation.

AC-12

Evidence objects read once per operation

must
Applicability
Modeunconditional
RationaleApplies to every engine operation that resolves receipt chains.
Constraint refs
  • CONSTRAINT-03
Guarantees
  • Each evidence object is loaded root-relative at most once and validated at most once per operation.
  • Each scan pass reads every reserved file exactly once; a workspace root's state is computed at most once per operation and reused.
  • The snapshot keeps its two-pass concurrent-change check.
  • Only fully validated objects are reused, keyed by content hash; an error or an absent object is never cached.
  • A snapshot never falls back to a root-relative read for a receipt-chain object; a referenced object missing from the scan fails closed.
Intent refs
  • SCOPE-09
Kindperformance
PreconditionsNone recorded
Scenarios
SCN-12-01

Scenarios

GivenA smaller and a larger repository of real receipt chains, the open-counting seam and a validation counter.
ThenRoot-relative loads and validations per evidence object stay at most one, and scan passes per operation are the same for both sizes.
WhenSnapshot, read, index, task-review and accept-scope each run once.
Source refs
  • SRC-03
  • SRC-04
StatementWithin one engine operation, each content-addressed evidence object (receipt, workflow event, observation, evidence context or authority source) is loaded through a root-relative read at most once and schema-validated at most once, however many receipts reference it. Reserved-output scans read each file once per scan pass, and the passes per operation are bounded by a constant: the snapshot's two-pass change check plus one per distinct workspace root, independent of the number of tasks or receipts. A snapshot validates reserved-output receipts from the bytes its scan already read.
TriggerAn engine operation (snapshot, read, index, task-review or accept-scope) resolves receipt chains.

Sections

SEC-PROBLEM

Problem

Blocks

On 2026-10-07 a hook BLOCK in a crashed session appended one line to the tracked `.codearbiter/gate-events.log`, staling all twenty verification and review receipts of the SMARTS build. The snapshot hashes every file on disk, so writes that never ship invalidate evidence. Separately, a snapshot takes 15-30 seconds on Windows because the store opens a handle for every ancestor of every file, twice; that pushed reply capture past Claude Code's 30-second UserPromptSubmit limit (#931).

References: SRC-02 SRC-04 SRC-05
SEC-APPROACH-ALTS

Approaches considered

Blocks
  • **Commit-bound evidence** (declined): requires per-task commits and still needs a clean-tree check, so a stray tracked append would still stale.
  • **Untrack gate-events.log** (declined): block history in a merged worktree would be lost at cleanup.
  • **Git ship set + fixed exemption + fewer handle opens** (selected).
References: SRC-05
SEC-RISKS

Risks

Blocks
  • Honoring .gitignore means a test that depends on ignored local state (stale node_modules, a locally built helper) can pass without staling evidence; exact-head hosted CI remains the backstop.
  • Machine-local ignore rules (.git/info/exclude, core.excludesFile) change membership without changing identity; files they hide also do not ship from that checkout.
  • Deliberate audit appends (/ca:override, triage) mid-round still stale evidence by design.
References: SRC-06
