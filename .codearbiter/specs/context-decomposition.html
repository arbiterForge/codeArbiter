Reviewed replacement for the Markdown plan: granular knowledge, bounded reads and human-readable native HTML. No second permission system. Current-source design only; implementation and release verification remain future work.

SEC-VERDICT

Review conclusion

Blocks

The original direction is sound, but the first plan is not safe to implement literally. It leaves admission-like selector behavior, whole-document finalization and a new runtime policy view insufficiently constrained. This revised proposal converts knowledge and retrieval, not authorization. It is a DRAFT spec/plan; no feature, migration, host test or release is claimed complete.

References: SRC-INPUT SRC-USER

This review is tied to current main at 0badb588dc1179b06e13db1ca5322590962b586a and the separately inspected open #1016 at 8c16bb1116c76ca0cbe69851d9f3d323764727fd. The Project registry references older heads; those remain historical. No GitHub source or Project registry was changed to produce this bundle. It supersedes the earlier Markdown plan for implementation guidance.

Blocks
ID / severityFindingRequired correction
R01 / HighAn existing selector can become a second permission system — _contextselectlib.py: compose_actor_input/check_task_context expose blocked and requires_actor_check and stop mutation for packet gaps.New HTML ordinary reads return records, omissions and unresolved facts, never admission/authorized/permission fields. Known real user stops and host rules remain independent. The actual action owner handles an actually required unresolved choice; unrelated tasks continue.
R02 / HighA generated runtime policy view adds unnecessary authority and staleness machinery — The proposed runtime view must be both cheap and trustworthy while source can change. The existing scope reader already has a small config contract.Do not add it. Keep activation in CONTEXT.md and the three operative path-scope blocks in a configuration-only security-controls.md. Move their narrative to HTML, and render any policy display as a derived read-only view. Two tiny operational exceptions, no duplicate editable policy.
R03 / HighBlanket initialization and evidence requirements can re-create an always-ask loop — Current context finalization expects thirteen outputs and valid provenance; current typed entries require evidence_refs even for drafts.New initialization checks structural availability and preserves disabled/stage settings; it does not demand completed interviews, every question answered, verified commands, receipts or thirteen semantically complete files. New draft entries accept explicit unknown/proposed provenance without invented evidence.
R04 / HighOld catalog scope can let unrelated corruption stop every task — repository/catalog.go scans all registered spec/plan files strictly, while kinds and cross-reads remain partially hard-coded.Targeted discovery/read loads only explicitly required kinds/artifacts under bounded limits. An unrelated broken decomposition page cannot prevent a valid feature task read. A targeted unreadable artifact is an honest read error, not a new permission decision.
R05 / HighBoard promotion can duplicate completed work — _taskboardlib.already_promoted checks OPEN entries only, and the previous plan proposed origin support as though it might not exist.Reuse the existing origin syntax and owner lock. Deduplicate across active and archived items; attach the board reference after the board write with retry by origin. Do not add a generic cross-store transaction framework.
R06 / HighSimply giving new names to .md paths misses active runtime consumers — Python selectors/snapshots/reports, the Pi TS activation reader, init finalization, version-aware code-map repair and source-bound site captures all need disposition.Use the explicit owner map and fresh literal plus semantic call-graph scan; classify each modify/verify/generate/retain. Do not treat canonical Python generation as coverage of independent TypeScript or metadata.
R07 / HighPlanned architecture must not become observed code or executable policy — Interview choices, brownfield discoveries, test results and configured rules have different owners and evidence.Use a small basis vocabulary: user-reported, source-observed, inferred, proposed, unknown. Declared commands are unrun. Decomposition owns desired architecture; code-map owns observed structure; link deviations without rewriting feature criteria or promoting narrative into policy.
R08 / MediumCross-artifact references need both a resolver and real HTML navigation — Current read and renderer commonly assume the one companion spec/plan; a generalized label is not an implemented codec.Add bounded same-repo one-hop resolution and root-relative identity-aware links. No network dereference, arbitrary depth, embeddings, database, or persistent retrieval ticket.
R09 / MediumUnclassified imported prose can disappear or flood every response — Imported context may lack paths, record types or trusted origin. Mandatory full inclusion makes selective retrieval pointless.Keep raw source bytes in the migration before-image; represent unresolved material as bounded notes with source offsets. Return pointers/counts and scoped uncertainty. Never call an omitted note nonexistent; expand the relevant note only when useful.

Benchmark representative small/large fixtures and report results. No proof-of-read, completeness score, forced extra model call, or blocked implementation because a packet is partial.

SEC-SYSTEM

Simple target design

Blocks

  security-controls.md       # existing operative +/- scope blocks only
  context/

    coding-standards.html    # relevant conventions and source references
    security-controls.html  # narrative observations/constraints, not policy authority
    code-map.html            # observed components and interfaces
  decomposition/
    project.html             # interview, intended architecture, phases, proposed work
  .provenance/               # existing descriptive source metadata
  .artifacts/                # existing journal and recovery data

The two Markdown exceptions contain operational settings, not a narrative mirror. CONTEXT.md remains the actual activation/stage owner. security-controls.md retains the existing migration-paths, ci-paths and deploy-paths blocks and their exact precedence. Move explanations into HTML; do not infer new enforceable controls from text. Existing custom/unknown settings are preserved, not truncated to meet a size target. HTML may show current config as a derived view, never as a second editable authority. This replaces the earlier proposed generated runtime view.

References: SRC-M04 SRC-M05

Use one small common record envelope: stable ID, kind, title, content, optional scope/references and descriptive basis. Specific command/component/work-item shapes extend it only where needed. Empty/unknown references are allowed for proposals and user-reported statements; sources become mandatory only for an actual source-backed claim. No generic graph store or per-field approval lifecycle. Existing HTML model/rendering is authoritative, never a manually synchronized JSON and Markdown copy.

References: SRC-M01 SRC-M02

Start with the native context and decomposition kinds plus an old-format read/import adapter. New projects use the complete supported format; old projects remain readable until an explicit selected conversion. Do not mix unsupported old clients into converted state and silently omit rules. This is one coherent PR with useful vertical slices, not a series of published partial formats.

SEC-RETRIEVAL

Retrieve what the work needs, not permission

Blocks

Known task: use task-context with current task identity and applicable path/component references; add selected criteria, explicitly linked context, effective relevant configuration pointers and directly linked decomposition intent. Unfamiliar topic: a bounded index/outline then one read-batch. Follow only requested same-repository records plus one explicit hop; deeper expansion is requested, not recursively fetched. Prioritize known global exclusions and relevant user instructions; do not reload all questions, provenance chains or renderer markup.

SEC-LIFECYCLE

Author, resume and refresh without a ceremony

Blocks

A greenfield draft can be saved with unanswered questions and proposed commands. The interview resumes the relevant unresolved choice, not a rigid first-unfinished phase that blocks independent work. Material choices reflect actual user statements; editing an implementation method or title does not ask again. If user confirmation is genuinely missing for a consequential outcome, ask that question once in ordinary language. Never make up user confirmation or a receipt.

References: SRC-M06

Ordinary typed edits use current revision/CAS and a unique operation ID. The engine may prepare a diff internally, but the caller does not have to paste a digest or secure a separate preview approval. Retry the identical request after an uncertain response; a conflicting write is a data-integrity error, not a permission problem. Preserve existing journal before-images and scope mutations to touched records.

References: SRC-M02 SRC-M08

Initialization means a supported structure is available, not that six interviews, all provenance, every proposed command and all human choices are complete. Disabled settings, explicit stops, actual host checks and stage remain unchanged during format conversion. Context freshness is advisory and record-specific. Unrelated source/title edits neither invalidate every packet nor restart reviewers. Do not turn context-check into mandatory six-domain reinspection.

References: SRC-M02 SRC-M03

Decomposition owns intended architecture/candidate work; code-map owns observed architecture; the board/execution plan owns actual task state; ADRs own accepted architecture decisions. Promotion uses existing origin markers and the board owner. Retry searches both open and archived rows; a crash after board creation but before adding its back-reference cannot duplicate the task. No automatic issue publishing, all-store lock or new task authority is added.

SEC-CUTOVER

Migration and damaged-state behavior

Blocks

Migration is a selected repository operation under existing authorization, not a background package-update side effect or permission check on ordinary reads. Preview the old-to-new ID/path mapping; preserve original bytes and unknown frontmatter. Commit the new authoritative state, descriptive provenance and format choice using the existing journal/lock primitives. Do not build a new migration service. Config-only scope blocks and activation stay readable through cutover.

References: SRC-M08

A missing requested record is a missing record, not an authorization refusal. An unrelated malformed artifact must not poison every catalog read. A damaged control file continues to use its existing host safety semantics; do not silently remove operative rules or invent a global context-denial policy. A current artifact with invalid checksum is an honest failed read/write, not a claim that the context is safe or complete.

References: SRC-M01 SRC-M05

Unclassified prose is retained as bounded note(s) with old-file/offset identity and unknown basis. Old raw bytes remain recovery evidence. Protect secrets and ignored paths with existing source-selection boundaries; generated HTML has no executable commands, network resources or external fetches. Scope matching normalizes worktree-relative paths and handles Windows case/Unicode, renames and missing files.

References: SRC-M08 SRC-M09

Prove restart after every relevant transaction boundary and idempotent repeated migration. Old incompatible clients are never promised compatible by a new marker. Prefer leaving existing projects on the old format until their intended cohort is supported. Before later writes, exact rollback can restore originals; after later edits, preserve current work through forward recovery/export, not a stale backup overwrite.
