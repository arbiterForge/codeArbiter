Decisions

DEC-01

Parent turn identity

Authorityproposed
ChoiceUse session_id + prompt_id to correlate a Bash PreToolUse/PostToolUse pair and an Agent PreToolUse/PostToolUse pair only. SubagentStart/SubagentStop are correlated by agent_id alone, never by prompt_id.
RationaleRecorded payloads show subagent lifecycle events carry the parent's CURRENT prompt_id: the second SubagentStop carried the next prompt's id, so an async reviewer that outlives the launching turn would never match.
Source refSRC-04
DEC-02

Verifier exit status

Authorityproposed
ChoiceSuccess is a PostToolUse event whose tool_response.stdout parses as exactly {request_id, state: COMPLETED} for the armed request and interrupted is false; a PostToolUseFailure event for the same tool_use_id marks the attempt failed.
RationaleClaude reports no exit code; the success/failure split is by event name.
Source refSRC-04
DEC-03

Claude launch envelope

Authorityproposed
Choicearm_request on Claude returns launch_envelope = {description, prompt, subagent_type: 'ca:authority-reviewer', model}; PreToolUse Agent tool_input must equal it exactly. Any other key (run_in_background, isolation, name, cwd) and subagent_type 'fork' are denied. The plugin ships ca:authority-reviewer with tools Read, Grep, Glob only; arming refuses when any project, user or CLI agent definition could shadow that name. The launch record stores tool_response.resolvedModel.
RationaleProject and user agent files override built-ins (documented precedence), so a built-in reviewer name is spoofable by the parent; a read-only plugin reviewer cannot edit what it grades, launch agents, or message its parent.
Source refSRC-04
DEC-04

Launch-to-child binding

Authorityproposed
ChoiceJoin launch and child order-independently: record Agent PostToolUse tool_response.agentId against the launch's tool_use_id, record SubagentStart by agent_id, and bind when both are present with agent_type equal to the pinned reviewer.
RationaleSubagentStop carries no tool_use_id, and the recorded Agent PostToolUse and SubagentStart landed in the same second, so their order is not established.
Source refSRC-04
DEC-05

First-Stop binding

Authorityproposed
ChoiceThe review result is the first SubagentStop for the bound agent_id with stop_hook_active false, agent_type ca:authority-reviewer, and a background_tasks list whose entry for this agent (if any) also names ca:authority-reviewer. Later Stops for that agent never change a recorded result; a first Stop failing these conditions rejects the request.
RationaleRecorded payloads show a second Stop for the same agent (stop_hook_active true, different final message), and that background_tasks is the parent session's list, which includes the running reviewer itself, so it can only corroborate identity.
Source refSRC-04
DEC-06

Engine profile

Authorityproposed
ChoiceAdd producer profile claude-review/0.1.0 with launch {parent_session_id, parent_prompt_id, tool_use_id, post_confirmed:true, agent_id, agent_type:'ca:authority-reviewer', subagent_type:'ca:authority-reviewer', model, resolved_model, first_stop:true}; review kinds accept codex-review/0.1.0 or claude-review/0.1.0, each only with its own launch schema. Bump the engine schema/protocol version as the compatibility rules require.
RationaleMapping Claude events onto the Codex profile would misstate the producer.
Source refSRC-02
DEC-07

Hook placement and cost

Authorityproposed
ChoiceRegister artifact-authority-hook.py as its own Claude hook entry; it exits 0 silently after one registry lookup when no request is armed.
RationaleKeeps pre-bash.py unchanged; the extra per-call cost is one registry directory read.
Source refSRC-07
DEC-08

Fixtures

Authorityproposed
ChoiceTests use the recorded Claude Code 2.1.281 payload shapes (identifiers and paths replaced) as fixtures.
RationaleGrounds the adapter in real host output rather than documentation.
Source refSRC-04
DEC-09

Hook output discipline

Authorityproposed
ChoiceOn success the Claude hook prints nothing and exits 0 (no permissionDecision allow, which would bypass user permission rules). It denies only via hookSpecificOutput.permissionDecision 'deny' with a reason on PreToolUse, and prints nothing on PostToolUse, PostToolUseFailure, SubagentStart and SubagentStop (never decision 'block' on SubagentStop, which would make the reviewer keep going).
RationaleClaude's output semantics differ from Codex's; recording authority must not grant permissions or alter the reviewer.
Source refSRC-01
DEC-10

Reviewer isolation channels

Authorityproposed
ChoiceAny SendMessage PreToolUse from the reviewer's parent session while a review is launching or running rejects that review (fail closed: the message shape is not a recorded contract). The wrapper Bash call is denied when run_in_background or dangerouslyDisableSandbox is true, when it carries any input key beyond command, description and timeout, or when its script is not the shipped artifact-authority.py beside the adapter.
RationaleCodex's fork_turns none has no Claude equivalent for mid-run steering; background Bash returns no stdout to corroborate.
Source refSRC-04
