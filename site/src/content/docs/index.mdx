<section class="ca-section ca-guarantees" aria-labelledby="ca-guarantees-title">
  <div class="ca-section-heading">
    <h2 id="ca-guarantees-title">What changes when codeArbiter is active.</h2>
    <p>Ask for the outcome. codeArbiter routes it to the lane that owns it, applies the gates the change needs, and ships through a pull request you approve. <a href="./concepts/gated-lanes/">How gated lanes work</a>.</p>
  </div>

  <ul class="ca-feature-grid" data-ca-layout="peers" role="list">
    <li class="ca-feature">
      <span class="ca-feature__icon"><ArbiterIcon name="gate" size="1.4rem" /></span>
      <h3>It stops at the tool boundary</h3>
      <p>Hooks run before shell and write calls. A blocked call never runs, whatever the model remembers.</p>
      <a href="./enforcement/">See what is enforced</a>
    </li>
    <li class="ca-feature">
      <span class="ca-feature__icon"><ArbiterIcon name="repository" size="1.4rem" /></span>
      <h3>The record lives in your repository</h3>
      <p>Specs, plans, decisions, tasks and audit logs live in <code>.codearbiter/</code>, so they move with the code and between hosts.</p>
      <a href="./codearbiter-directory/">Explore the state store</a>
    </li>
    <li class="ca-feature">
      <span class="ca-feature__icon"><ArbiterIcon name="audit" size="1.4rem" /></span>
      <h3>Every bypass leaves a trail</h3>
      <p>Overrides, autonomous decisions and review findings are written down, so you can audit a range later instead of reconstructing it.</p>
      <a href="./concepts/auditability/">See the audit model</a>
    </li>
  </ul>
</section>
