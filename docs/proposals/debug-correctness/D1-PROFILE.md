# D1 finite profile and validation boundary

Status: source-only design freeze for T03, not a runtime implementation or native approval. Read with CONTRACT.md. This leaf owns the previously undecided primitive/process profile; it does not duplicate the packet field model. Protocol and all AC/SEM/V identities remain unchanged.

## Timestamp profile: debug-rfc3339/1

Use a deliberately finite RFC3339 subset: four-digit year 0001-9999; real Gregorian month/day including century leap-year rules; ASCII T or t; hours 00-23, minutes/seconds 00-59; optional dot plus 1-9 ASCII fractional digits; Z/z or a signed HH:MM offset with hours 00-23 and minutes 00-59. Preserve input spelling and fractional precision. Do not round, strip, normalize to local time or infer an offset. Accept -00:00 as RFC3339's unknown-local-offset representation; preserve that fact, never infer a known local timezone. UTC instant comparison is separate from validating the supplied date/time representation.

Reject year zero, leap-second 60, 24:00, zone names/annotations, spaces replacing T, comma fractions, offset seconds, missing timezone, malformed calendar dates, extra fractional digits and trailing whitespace/controls. These explicit exclusions mean this is NOT full RFC3339 acceptance. Null remains valid where the parent field is nullable and carries the required limitation. The generated schema uses both a full-string profile pattern and asserted date-time checking; format alone is insufficient. Native parsing and conformance cases must agree on this subset, including lowercase and offsets. Source references: https://www.rfc-editor.org/rfc/rfc3339 sections 4.3, 5.6 and 5.7; no RFC9557 annotations are accepted.

## Numbers, Unicode and identity

Determine mathematical integrality from the exact JSON decimal value, not binary floating point. 0, -0, 0.0, -0.0, 1e3 and 10e-1 are integers; true, false and 1.5 are not. 1e-4000 is nonzero/nonintegral and 1.0000000000000000000001 is nonintegral; neither may round into acceptance. 1e4000 is mathematically finite/integral despite overflowing binary float. JSON NaN and Infinity tokens reject. Preserve existing no-extra-range semantics for exit_code. Implement bounded lexical/exact-decimal reasoning: do not expand huge exponents, convert them to unbounded machine integers, change Python global limits, or allocate exponent-sized buffers. A zero coefficient remains zero regardless of a syntactically valid exponent. The existing packet-byte bound also bounds numeric lexemes. Source reference: https://json-schema.org/understanding-json-schema/reference/numeric .

Text length counts decoded Unicode scalar values, not UTF-8 bytes, UTF-16 units or grapheme clusters. Valid paired surrogate escapes decode to one scalar; lone/escaped surrogates and malformed/overlong UTF-8 reject. No NFC/NFD normalization or silent trimming. The non-whitespace test uses this explicit stable set: U+0009-U+000D, U+0020, U+0085, U+00A0, U+1680, U+2000-U+200A, U+2028-U+2029, U+202F, U+205F, U+3000. Strings entirely in that set fail text(N); surrounding whitespace on meaningful text is preserved. Other control handling remains the parent field contract; identifiers/locators are never interpreted as instructions. ID checks use whole-string matching. The generated schema must not use a dollar anchor that accepts a final newline as its only end condition.

Keep UTF-8 byte and decoded-character ceilings separate. Reject a BOM, a second JSON value, duplicate object keys after escape decoding, and non-JSON trailing data; JSON trailing space/tab/CR/LF is permitted within the 65,536-byte ceiling. Root container depth is 1; child objects/arrays add one; scalars add zero. Cap scanning before recursive decoding. Never truncate or repair invalid input.

Initial producers emit fingerprint=null and fingerprint_recipe=null, with limitations and targeted current-state checks. Do not introduce a hashing subsystem in D1 or D2 merely to populate optional metadata. Retained non-null pairs are inert historical metadata: recipe grammar is a local profile name and version (`[a-z][a-z0-9-]{0,63}/[1-9][0-9]{0,3}` as a full-string match). No recipe URL, code, dynamic resolver or execution. The initial consumer has no newly qualified fingerprint recipe; it therefore rechecks relevant source/index/runtime evidence rather than trusting such a pair. Grammar validity is not proof the recipe is documented, computed, supported or current. This freezes the omission option already permitted by SPEC R04; it does not silently verify old fingerprints.

## Private validation process

The only operation is `validate`, supplied to the resolved installed helper using the selected Python 3 with -B. No root, input-path, schema-path or executable option is accepted. Validate arguments before reading stdin. Input is a finite, fully materialized byte stream from the caller; the caller applies the existing host timeout and output controls. Read at most 65,537 bytes. The helper is not an arbitrary process supervisor, downloader, writer or authority producer.

Normal output has exactly protocol, valid, errors and truncated, in that order. Protocol is codearbiter.debug-validation/1.0.0. Errors are closed objects with exactly code and path. Success is valid=true, errors=[], truncated=false, exit 0. Invalid input or invocation is valid=false and exit 2. A recoverable internal/input-I/O fault is valid=false and exit 3. Allowed diagnostic codes: USAGE, INPUT_IO, INPUT_LIMIT, DEPTH_LIMIT, INVALID_UTF8, INVALID_JSON, DUPLICATE_KEY, UNSUPPORTED_PROTOCOL, REQUIRED_FIELD, UNKNOWN_FIELD, TYPE, VALUE, REFERENCE, SEMANTIC, INTERNAL. No caller-selected diagnostic codes or arbitrary exception text.

At most 16 errors, path at most 256 ASCII characters, complete stdout at most 8,192 UTF-8 bytes including its LF. Paths contain only known model field names and bounded array indices, rooted at $. An unknown input key is reported at its parent, never echoed. Syntax/decoder errors use $. Diagnostics follow fixed decoder priority, then model-field declaration order and array index order, then SEM order. Stop collecting after the ceiling and set truncated=true if further errors were suppressed. Structural failure may prevent later semantic checks; do not fabricate them. Preserve original input bytes/values privately; output no packet, rejected value, secret canary, traceback or environment.

Use deterministic UTF-8 JSON with a final LF; stderr is empty for normal valid/invalid outcomes. If the interpreter cannot start, stdout cannot be written, or the process is killed, a complete JSON envelope is not promised. A nonzero exit, timeout, missing/truncated envelope, wrong protocol or inconsistent valid/errors combination blocks the caller. No second interpreter attempt or fallback to unvalidated prose. Import-bytecode suppression must precede local imports; own installed-code reads are allowed, project reads/writes, cache/temp files, child processes and network are not.

## Review and conformance boundary

D1-CASES.json freezes primitive controls, every SEM negative obligation, original example identities and permitted scenario outcomes. It is an evaluator-side design input, not executable proof. D2 must run the generated schema with asserted formats and exact-number handling against actual production validation; do not use default float loading to erase a counterexample. Pure validation cannot decide causal truth, real permissions, freshness, effects, or test adequacy. These remain named consumer/host/model/review obligations. Product results and native approval remain pending.
