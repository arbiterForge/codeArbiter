## T-005: internal scout-report decoder

Canonical source: `core/pysrc/_contextreportlib.py`; the three host copies are generated by `tools/sync-core.py`. Its one entry is `decode_report(payload, expected=...)`, with bounded code-owned `ReportError` diagnostics. There is no new public command, hook, service, file writer or dispatch loop.

The caller supplies the assignment ID, attempt ID, snapshot ID and exact path/category scope. The closed v1 envelope must match those bindings. Duplicate JSON keys, unknown fields/enums, malformed ranges/digests, unsafe lexical paths, oversized/deep payloads and unexpected category membership reject. Raw and normalized report content are bounded at 48 KiB per report, with additional count/depth/text limits in the codec. This does not implement the separate 48 KiB joined-synthesis limit; the future orchestrator must enforce that aggregate boundary.

Transport status is complete, failed or oversize. Failed/oversize transport cannot carry salvaged findings as a completed report. Complete reports account for every assigned category, including visible gaps. Category status preserves observed, not_applicable, not_found_in_scope, not_inspected, ambiguous, failed and oversize. A complete ambiguous report is not a failed transport and does not make its uncertain findings established facts.

Confidence maps exactly: strong/HIGH/high to high, moderate/MEDIUM/medium to medium, and weak/LOW/low to low. Other spellings and invented values reject. Inapplicability requires a reason and evidence; negative search requires bounded search coverage. Findings use category-specific names and bounded named values, with non-dangling evidence references. There is no approved-policy, verification-passed or command-execution field.

Final review exposed a mixed-identity hole: two categories could cite the same source with different digests. Three new negative assertions reproduced that defect in the first implementation. The corrected decoder rejects a conflicting digest for the same path and digest method across the whole report, including case aliases. Named raw SHA-256 and normalized Git SHA-1 remain incomparable rather than being mistaken for matching identities. The positive cross-category and mixed-method controls pass.

This parser does not read the filesystem, resolve symlinks, acquire trusted snapshots, detect every secret in text, establish factual truth or authorize work. Report values remain untrusted evidence. Matching a caller-supplied snapshot is not proof that a host actually inspected it. Real snapshot acquisition, scoped joins, six-domain dispatch, isolation, semantic reconciliation and publication remain later plan work.

## T-003: test-owned observation and accounting

The finite contract lives in `.github/scripts/test_context_evaluation.py`; `.github/fixtures/context-onboarding/observation.schema.json` is generated from `observation_schema()` and checked for exact shape equality. Neither file is a new production metadata store or an always-loaded schema. The checker accepts only its own finite JSON Schema subset, not arbitrary external schemas.

Observations identify the host/package/profile, source snapshot, launched attempts and recorded outcomes, limits, loading evidence, token/cache convention and separately sourced monetary amounts. Unknown measurements stay unknown. Missing/duplicate/orphan attempts cannot become complete usage. The summary counts failed/retried attempts and synthesis/review/task work as well as scouts. Inclusive versus exclusive cache accounting is explicit, so cached tokens are counted once. Known partial measurements can already exceed a bound while the full total remains unknown.

The launch inventory can record over-budget runs instead of rejecting their existence: aggregate scout count, retry, subdivision depth and fanout overruns remain visible. This is retrospective accounting, not a dispatcher enforcing a launch limit. The caller must supply trustworthy capture and actual profile-specific authorization before paid work. Provider labels or a reference string alone are not provenance proof.

Loader events and model self-reports are not promoted to measured effective input. Synthetic-loading observations cannot claim a successful task. Reported task outcomes require evaluator-side references but do not become an approval/ready result. Monetary amounts are decimal, separately sourced and separated by currency; no prices, exchange rates or savings are invented from token counts.
