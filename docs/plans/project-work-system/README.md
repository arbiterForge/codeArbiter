## Start here

Read `SEC-OUTCOME`, `SEC-IDENTITY`, `SEC-INTERFACE`, `SEC-COMMITS` and `T-001`.
Use the installed manifest-pinned bridge for identity/outline/exact reads. A
fresh local checkout may need the existing `init-store` operation; it creates
local store metadata, not authority. Do not commit the local store or read tickets.

First useful journey: create one durable local item, attach a real current
spec/plan, record progress with an unknown check, retrieve bounded relevant
context and render its combined work view. Then extend initialized brownfield
acquisition and one actual external adapter. Do not create all backends first.

## Recommended scope

Local work and legacy compatibility plus GitHub Issues / optional Projects.
Jira and Linear are extension targets, explicitly unsupported until implemented.
Specs and plans stay distinct; vertical work folders are generated views first,
not a breaking relocation of the canonical documents. One writable owner per
field; no duplicated plan-task status or global question/decision authority.

Local changes continue to ride work commits. Remote effects cannot commit
atomically with Git. Contingent sends default to merge-observed sync; independent
immediate creation or sync-now is explicit. This scoped ADR-0008 extension is a
proposed design choice, not an already-accepted ADR or a new per-item approval.
ADR-0043 remains the hard design boundary: information and coordination, never
another permission system.
