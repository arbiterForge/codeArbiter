Release, rollback and research follow-throughTop

Checkpoint 1 freezes both schemas and the source-consumer inventory. Checkpoints 2–4 build the file mechanism and complete the existing workflow path. Checkpoint 5 handles selected legacy pairs and cold installation. Checkpoint 6 completes generated-host, native-platform and end-to-end proof. No checkpoint is independently permission to enable only half the workflow in production.

Default enablement waits for both artifact kinds, full consumer closure and native support evidence. Use selected fixture projects first; no automatic repository-wide conversion. Keep legacy reading explicit throughout. Backups and migration receipts retain exact old/new identities.

Rollback stops new dispatch, preserves newly produced evidence and returns through a reviewed compatibility/reconciliation path. Restoring an older binary alone cannot safely reinterpret new HTML state. A conversion after additional HTML edits needs a loss report rather than a silent reverse transformation.

Research follow-through is a separately budget-approved pilot, not autonomous model spend hidden in a test command. Compare current Markdown specs/plans, semantically equivalent structured specimens, and contract-enriched specimens under pinned models/harness snapshots. Repeated trials and independent acceptance checks should measure correctness, omissions, review/repair effort and total cost. Do not infer superior performance merely from valid schemas.
